# 0.10.5 建筑台部署卡死修复

使用当前玩家存档的只读副本，在原始安装版0.10.4的Windows程序复现：空地位置(336,220)预览约1.417毫秒，相邻障碍位置(328,220)耗时5055.145毫秒。该副本有180个目标点、1862处逻辑障碍，地图7200×6400；预览缓存每0.2秒到期后重复检查，实际表现为持续卡住。原始存档始终不是测试写入目标。

根因是grounds.placement_error对所有村民和设施逐个运行放置前／放置后的全地图A*，再恢复共享导航网格。地形分隔导致不可达目标的寻路反复搜索大区域；临时重建也会改变导航revision。

修复将可达性判断委托navigation.preserves_access。accessibility.gd以每行连续空格段构建连通区域，在原始网格快照上覆盖候选障碍／搬动原物件／开放栅栏门的增减计数。四邻接连通与原禁止穿角的八邻接路径具有相同可达性，端点仍在附近49格内选择最近空格。缓存随真实障碍集合变化失效；候选只复制变化行并复用相同预览，原网格与revision不被预览修改。main入口无需业务变更，编辑器与production继续拥有成品部署、库存及持久化事务。

保留土地保护、已有碰撞、入口空间、围栏通路、栅栏门例外、搬动与回收、存档失败回滚及0.10.4房屋／矿洞切换修复。没有调整配方、资源数量、角色属性、游戏计时或存档格式。

回归入口tests/building_deployment_probe.tscn，必须设置AIU5_BENCH_DIR为独立目录。40组确定随机障碍图与原A*结果对照，另测单通路封堵、移除障碍、重叠计数更新、负坐标与边界端点；实际游戏测试建筑旁20个预览位置、鼠标确认、物品恰好扣一、无效放置不扣物、建造菜单、搬动回收、失败回滚和重新加载。Windows实际程序与源码均使用隔离新档及私有玩家副本。

实际结果见VERIFICATION_0.10.5.json；未执行检查不记录为通过。本次仅更新本地程序、安装包和完整镜像，不提交或发布GitHub。
