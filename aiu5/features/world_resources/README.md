# 按存档种子生成资源

`generator.gd.configure(seed, fixed_obstacles)` / `chunk(Vector2i)` 返回稳定ID、世界坐标、类型与外观变体的纯数据。固定320×200区块，显式32位整数PRNG按种子/区块/版本混合，不依赖访问顺序、全局随机数或墙上时间；当前算法版本1，修改位置算法、静态避让规则或资源ID规则时必须升级版本并提供迁移，不能静默用新规则重算旧档。存档菜单拒绝不支持的生成版本。

每区块最多7个新增资源，干旱带偏向3—4棵枯木，山脚偏向4—6个石矿，靠近绿洲的数量更少；碰撞和禁区会减少实际数量。保留原六棵枯木、十个地表石矿及地下矿脉；这些旧ID与占位区即使采尽也不变化，不会挤动新生成对象的ID。房屋规划用地、门口、道路、水域、桥岸、高山实体、祭台、农田、猪圈/牛棚和出生区域均避让。资源脚下互不堵碰撞，人物/动物当前占位时延迟创建，防止在脚下生成碰撞。

`resources.gd.start(world, inventory, harvesting, mining, farming, grounds)` 在玩家部署物恢复前抓取固定障碍；`focus(at, indoors)` 由streaming调用，提前两圈准备数据、附近3×3创建节点，外圈节点临时退出树，超过两圈释放。每帧最多准备1个区块数据、创建2个资源节点，2毫秒软预算；单个生成或导航更新可能超过预算。描述数据缓存最多25区块，物件也有范围上限；打开全图和暂停菜单停止该模块，房屋内停止生成。当前视野资源按队列逐步出现。

动态节点标记procedural_resource，由本模块独立拥有；streaming忽略它们，避免重复停用/释放。harvesting/mining提供add_procedural接口并维护当前生成对象索引；原采集条件、木头/石料产量与满包保护复用原规则。

`export_state()` / `restore(data)` 保存seed/version/suppressed；砍伐hit在库存harvesting表，矿物hit在session.mining.progress表。只存已修改的进度，不存完整远区节点；采尽对象不再创建、没有碰撞与交互，部分对象按原坐标和hit恢复。已有农田或玩家部署物与候选重叠时保留玩家物件并持久化排除该资源。普通区块重载与退出续玩不会复原资源；主动祭台回退仍按回退点恢复采集状态，旧回退点未含seed时继续使用此存档原种子。

新存档slot.json创建时保存随机seed；完整快照的resource_world同步保存。之前无seed的槽位首次选择时补一个随机seed并写元数据；快照已有seed则优先保留。测试直接实例化main且没有槽位元数据时按隔离路径取得稳定默认值，正式入口使用槽位种子。全部在本地Godot运行，无网络或模型调用。

测试：tests/world_resources_smoke.gd覆盖确定性、访问顺序、禁区、密度、预算、真实E采集、建造碰撞、跨区释放/重载、旧农田保护、重启和祭台回退；tests/resource_quit_smoke.gd及其verify第二进程检查全图暂停时窗口关闭与远区采集状态恢复。启动和测试命令见根README。

森林使用独立features/forest模块与forest1稳定ID，旧沙漠gen1资源及采集记录保持。focus支持负区块，负区块不生成沙漠枯木/石矿；森林草药与林木仍只在附近创建。


0.10.0：density.gd以种子和稳定ID筛选枯木60%／其他80%，描述生成顺序及幸存坐标不变，采集进度兼容。
